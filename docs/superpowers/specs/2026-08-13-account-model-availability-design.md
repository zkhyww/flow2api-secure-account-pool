# 账号模型可用性设计

## 目标

让测试页按当前诊断账号清楚区分模型状态，避免用户依靠模型名猜测，同时保持现有 `/v1` API、模型 ID、请求体和账号池调度行为完全不变。

## 状态口径

- `available`：该账号使用该公开模型 ID 完成过真实生成，且结果包含媒体。
- `unavailable`：该账号使用该公开模型 ID 明确收到 `model_access_denied` 或 `membership_tier`。
- `unknown`：没有真实结论，或只发生过验证码、额度、限流、内容审核、网络、上游 5xx、媒体解析等不能证明模型不可用的问题。
- 后续成功可以把旧的 `unavailable` 更新为 `available`；临时失败不得覆盖既有结论。

## 数据与兼容边界

- 新增独立的 `account_model_availability` 表，以 `(token_id, model)` 为唯一键；不把新字段塞入 token、task 或现有日志结构。
- 仅保存白名单元数据：`token_id`、公开模型 ID、状态、公开错误类、成功/明确拒绝次数和时间戳。
- 不保存提示词、媒体 URL、Cookie、Token、响应正文或浏览器状态。
- 初始化时可从已有 `tasks` 的 `status/model/token_id/has_media/error_class` 元数据安全回填，不读取 prompt 和 result URL。
- 公共 `/v1/models` 与 `/v1/chat/completions` 不变；新增状态查询仅供已登录管理测试页使用。

## 页面行为

- 诊断账号变化时重新加载该账号的模型状态。
- 绿色：`已验证可用`；红色：`当前账号不可用`；黄色：`待验证`。
- 默认“推荐视图”优先展示绿色；若该账号尚无绿色记录，展示适合优先测试的黄色模型，避免空白页。
- 红色和其余黄色模型折叠在“其他模型”中，用户可主动展开，仍可选择和调用。
- 显示易懂名称，但提交请求始终使用原始模型 ID。

## 自动记录

- 正常图片或视频任务成功且 `has_media=true` 后记录 `available`。
- 明确的 `model_access_denied` 或 `membership_tier` 记录 `unavailable`。
- 其余失败不改变可用性状态。
- 测试页指定账号与自动账号池任务都复用同一记录入口，不额外生成、不浪费积分。

## 验收

- 旧 API 合同测试保持通过。
- 数据库迁移幂等；同账号/模型只有一行。
- 账号 A 成功不影响账号 B。
- 明确拒绝变红，临时失败不变红，后续成功可恢复绿色。
- 页面切换账号后状态随账号变化；提交的模型 ID 不变。
- 全量测试、compileall、`git diff --check` 通过。
